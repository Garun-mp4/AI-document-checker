# AI Document Checker

Локальный веб-сервис для чтения документов: семь ответов по содержанию, поиск с цитатами и чат. Интерфейс и все данные приложения рассчитаны на одного пользователя.

## Запуск

Требуются Docker Desktop с Compose и интернет для первичной загрузки контейнеров и локальной модели эмбеддингов.

1. Скопируйте `.env.example` в `.env` и при желании задайте собственный пароль PostgreSQL латинскими буквами и цифрами. Не добавляйте `.env` в Git.
2. В каталоге проекта выполните:

   ```powershell
   docker compose up --build -d
   ```

3. Откройте [http://localhost:5173](http://localhost:5173).
4. Нажмите **Подключить Codex**, откройте ссылку активации и введите показанный одноразовый код. Состояние входа хранится в отдельном Docker volume.
5. Загрузите документ. После локального извлечения текста и индексации появятся карточки анализа; вопросы чату можно задавать в правой панели.

Проверить состояние контейнеров: `docker compose ps`. Посмотреть сообщения API: `docker compose logs -f api`. Остановить приложение: `docker compose down`. Обычная остановка сохраняет БД, загруженные документы, модель и вход Codex. Команда `docker compose down -v` удалит эти volumes вместе с данными.

## Обработка данных

Оригиналы, сформированный Markdown и карта источников хранятся в Docker volumes на локальной машине. MarkItDown `0.1.8` запускается внутри API-контейнера как библиотека с отключёнными plugins; host CLI и MCP для runtime не требуются. Векторные эмбеддинги создаются локальной мультиязычной моделью `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` (384 измерения); кэш модели и Hugging Face сохраняется в отдельном volume. PostgreSQL с `pgvector` хранит Markdown-фрагменты и векторные индексы. Для ответов в облачный Codex передаются только выбранные релевантные фрагменты Markdown и вопрос. Оригинал, полный Markdown и локальный индекс туда не загружаются.

Для ответов используется официальный Python SDK `openai-codex`, авторизация Codex через аккаунт ChatGPT и выбранные в интерфейсе модель и уровень reasoning. По умолчанию используются `gpt-6-luna` и `medium`; после входа в модальном окне **Подключение модели** доступны только варианты из каталога вашего аккаунта. Выбор сохраняется в отдельном файле Docker volume `codex_auth` и применяется после перезапуска контейнера. OpenAI API key не нужен. Нужны интернет, активный вход в Codex и доступность выбранной модели; приложение показывает ошибку вместо автоматической подмены модели. Лимиты и доступность зависят от аккаунта Codex.

## Поддерживаемые форматы

- PDF с доступным для извлечения текстом (положение источника: страница). Зашифрованные, повреждённые и сканированные PDF отклоняются; OCR не реализован.
- DOCX (абзацы и строки таблиц), TXT и MD (диапазоны строк), CSV (строки и числовые агрегаты), XML (путь элемента).
- XLSX и XLS (листы, строки и ячейки), PPTX (слайды и блоки текста), HTML/HTM (без выполнения скриптов), JSON (JSON path) и EPUB (главы).
- Максимальный размер одного файла: 25 MiB. Изображения, аудио, произвольные ZIP-файлы и URL-источники не принимаются.

Ответы по документу имеют ссылки на серверные источники. Цитаты ведут к извлечённому фрагменту и его исходной координате; ответ без подтверждённых источников явно сообщает об отсутствии сведений. Для CSV сумма и среднее числовых столбцов рассчитываются в коде.

## UX

Слева находится история чатов: каждый загруженный документ создаёт отдельный устойчивый чат. В строке видны название (имя файла или первый вопрос), число сообщений и последняя активность. История вопросов и ответов хранится в PostgreSQL, поэтому обновление страницы не сбрасывает работу; выбранный чат дополнительно восстанавливается в этом браузере. Для продолжения нажмите на чат в списке.

Предпросмотр оригинала и семь карточек находятся по центру, чат — справа. В просмотрщике доступны вкладки **Оригинал** и **Markdown**, а готовый Markdown можно скачать. Для PDF и DOCX отображаются страницы, для TXT/MD/XML/JSON/HTML — безопасный исходный текст, для CSV/XLSX/XLS — таблица, для PPTX и EPUB — структурированные исходные блоки. Нажатие на цитату прокручивает оригинал к странице, абзацу, строке, слайду, листу или узлу и выделяет связанный фрагмент; при неточном сопоставлении показывается ближайшая область. Если MarkItDown недоступен, документ остаётся готовым в резервном native-режиме с предупреждением. Ширина чата меняется мышью или клавишами-стрелками и сохраняется в браузере; панель можно свернуть или развернуть. На узком экране библиотека и чат открываются как выдвижные панели.

Визуальный язык следует приложенному брифу на основе Uber: Inter, чёрно-белая палитра, отступы по шкале 4 px, пилюли для кнопок и карточки с радиусом 16 px. Это вдохновлённая адаптация, а не официальный продукт Uber.

## Разработка

- `backend/` — FastAPI, SQLAlchemy, миграции Alembic, парсеры, поиск и Codex SDK.
- `frontend/` — React, TypeScript, Vite, nginx.
- `docker-compose.yml` поднимает PostgreSQL/pgvector, API и веб-клиент.

API доступно через `/api/v1`; библиотека чатов — `GET /api/v1/chats`, интерактивная OpenAPI-справка — [http://localhost:5173/docs](http://localhost:5173/docs). API-порт остаётся внутри сети Docker Compose.

## Проверки

Локальные проверки устанавливаются отдельно от runtime-зависимостей:

```powershell
cd backend
python -m pip install -r requirements-test.txt
python -m pytest -q
```

Для проверки полного API-потока используйте отдельный Compose-проект. Его PostgreSQL, файлы, авторизация Codex и кэш эмбеддингов изолированы от рабочего приложения. Уникальный проект без входа Codex позволяет проверить извлечение текста и локальную индексацию, не отправляя тестовые документы облачной модели:

```powershell
$env:WEB_PORT = "5174"
docker compose -p document-checker-integration up --build -d
cd backend
$env:AI_CHECKER_BASE_URL = "http://localhost:5174"
python -m pytest -q -m integration
cd ..
docker compose -p document-checker-integration down -v
Remove-Item Env:WEB_PORT
Remove-Item Env:AI_CHECKER_BASE_URL
```

Набор создаёт синтетические документы всех поддерживаемых форматов, проверяет MarkItDown, карту соответствий Markdown → оригинал, fallback, ссылки на источники, индексацию, API-предпросмотр, таблицы, CSV-агрегаты, скачивание Markdown и безопасность путей. Отдельные unit-тесты проверяют якоря, соотношение сторон, табличные строки, расчётные блоки и миграцию артефактов. Интеграционные тесты также проверяют контракт статуса Codex. Обычный `pytest -q` оставляет Compose-тесты пропущенными, если `AI_CHECKER_BASE_URL` не задан.
