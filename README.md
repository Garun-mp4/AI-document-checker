# AI Document Checker

Локальный веб-сервис для чтения документов: семь ответов по содержанию, поиск с цитатами и чат. Интерфейс и все данные приложения рассчитаны на одного пользователя.

## Запуск

Требуются Docker Desktop с Compose и интернет для первичной загрузки контейнеров и локальной модели эмбеддингов.

1. Скопируйте `.env.example` в `.env` и при желании задайте собственный пароль PostgreSQL латинскими буквами и цифрами. Не добавляйте `.env` в Git.
2. В каталоге проекта выполните:

   ```powershell
   docker compose up --build -d
   ```

3. Откройте [http://localhost:5173](http://localhost:5173).
4. Нажмите **Подключить Codex**, откройте ссылку активации и введите показанный одноразовый код. Состояние входа хранится в отдельном Docker volume.
5. Загрузите документ. После локального извлечения текста и индексации появятся карточки анализа; вопросы чату можно задавать в правой панели.

Проверить состояние контейнеров: `docker compose ps`. Посмотреть сообщения API: `docker compose logs -f api`. Остановить приложение: `docker compose down`. Обычная остановка сохраняет БД, загруженные документы, модель и вход Codex. Команда `docker compose down -v` удалит эти volumes вместе с данными.

## Обработка данных

Оригиналы, сформированный Markdown и карта источников хранятся в Docker volumes на локальной машине. MarkItDown `0.1.8` запускается внутри worker-контейнера как библиотека с отключёнными plugins; host CLI и MCP для runtime не требуются. API принимает запросы и читает сохранённые результаты, а тяжёлые parser/OCR/MarkItDown/embedding операции выполняет worker. PDF классифицируется постранично: качественный текстовый слой сохраняется, OCR запускается только на сканах и подозрительно неполных страницах, пустые страницы пропускаются. Для OCR-коробок хранятся нормализованные координаты слов и строк с учётом поворота и CropBox; citation подсвечивает диапазон на неизменённом оригинале. Worker-контейнер содержит Poppler и Tesseract (`rus+eng`), OCR ограничен 100 страницами, 5 млн символов и таймаутом 90 секунд. Векторные эмбеддинги создаются локальной мультиязычной моделью `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` (384 измерения); кэш модели и Hugging Face сохраняется в отдельном volume. PostgreSQL с `pgvector` хранит Markdown-фрагменты и векторные индексы. Для ответов по документу в облачный Codex передаются выбранные релевантные фрагменты Markdown, вопрос и ограниченная история того же чата (до 32 сообщений и 12 000 символов). Оригинал, полный Markdown и локальный индекс туда не загружаются.

Голосовой ввод в composer использует только браузерное локальное распознавание русского языка. Оно доступно, только если браузер подтверждает `SpeechRecognition.processLocally` и установленный пакет `ru-RU`; если такой режим недоступен, приложение оставляет обычный ввод включённым и показывает причину. Аудио не загружается в приложение и не сохраняется им. Распознанный текст вставляется в черновик у курсора, его можно проверить и отредактировать; сообщение отправляется только после отдельного действия пользователя. Языковые пакеты автоматически не загружаются.

В начальном окне можно открыть отдельный сохраняемый чат **Помощь по приложению**. Он отвечает по проверенному каталогу функций; прикреплённый документ не включается в контекст такого вопроса. В документном чате вопрос о функции приложения использует совпавшие записи каталога; фрагменты документа добавляются только для смешанного вопроса о приложении и содержании документа. История ограничена текущим чатом. Для нового потока помощи SDK получает `ephemeral=True`, но этот режим сам по себе не гарантирует отсутствие внешнего хранения у удалённого провайдера. Ответы ссылаются на серверно проверенные записи каталога или фрагменты документа; неизвестные функции не получают выдуманных источников.

Если ответ подтверждён каталогом и текущей сборкой, в сообщении появляется действие **Показать в интерфейсе**. Оно доступно только после нажатия пользователем, прокручивает страницу к единственной доступной цели и ненадолго обводит её; настройка или кнопка за пользователя не активируется. Для скрытой, занятой, перекрытой, неоднозначной или устаревшей цели остаётся текстовая инструкция без подсветки.

Обработка выполняется устойчивой PostgreSQL-очередью в отдельном `worker`-сервисе. Состояния заданий и версии результата сохраняются в БД, поэтому перезапуск worker не теряет оригинал, активный анализ или чат. Для диагностики доступны `GET /api/v1/documents/{id}/jobs`, `POST /api/v1/documents/{id}/cancel` и повторная операция через `POST /api/v1/documents/{id}/retry?operation=analysis|process`. Подробные правила восстановления и отмены описаны в [docs/M03_PROCESSING.md](docs/M03_PROCESSING.md).

Для PDF в просмотрщике доступны статусы распознавания каждой страницы и повторный OCR всего набора страниц, требующих распознавания, либо выбранной группы страниц. Язык можно задать как русский, английский или оба языка; пресеты используют 150, 200 и 300 DPI. За одно задание обрабатывается не больше `OCR_MAX_PAGES` страниц (по умолчанию 100). Новая версия текста и ответов публикуется только после успеха; оригинал и чат остаются доступными, а старые citations разрешаются по прежним source ID. Порог предупреждения настраивается через `OCR_CONFIDENCE_WARNING_THRESHOLD` (0–100, по умолчанию 60). Оценка Tesseract служит эвристикой для проверки страниц и не является вероятностью правильности текста. Просмотр оригинала не запускает OCR автоматически.

Для ответов используется официальный Python SDK `openai-codex`, авторизация Codex через аккаунт ChatGPT и выбранные в интерфейсе модель и уровень reasoning. По умолчанию используются `gpt-6-luna` и `medium`; после входа в модальном окне **Подключение модели** доступны только варианты из каталога вашего аккаунта. Выбор сохраняется в отдельном файле Docker volume `codex_auth` и применяется после перезапуска контейнера. OpenAI API key не нужен. Нужны интернет, активный вход в Codex и доступность выбранной модели; приложение показывает ошибку вместо автоматической подмены модели. Лимиты и доступность зависят от аккаунта Codex.

Локальные размеры, безопасная очистка временных файлов и кэша, удаление выбранной части или всей библиотеки, а также выгрузка приватно ограниченной диагностики доступны в меню **Локальные данные**. План удаления показывает точное содержимое и требует фразу подтверждения; авторизация и активные данные защищены. Правила очистки и резервного копирования PostgreSQL и originals volume, безопасное восстановление в отдельный Compose-проект и изолированная проверка описаны в [документе M15](docs/M15_LOCAL_DATA.md).

## Защита загрузок (M02)

Размер проверяется при чтении HTTP body и файла; MIME сопоставляется с сигнатурой и структурой. Office/EPUB имеют пределы внутренних ресурсов и запрет опасных путей/внешних загрузок. Парсеры, MarkItDown, OCR и таблицы работают в ограниченных дочерних процессах без сетевого доступа; API сохраняет соединения с БД и Codex. Linux-защиты CPU/памяти/сети включены в штатном Docker Compose. HTML/XML оригиналы открываются как безопасный текст, а не активная веб-страница. Подробнее: [границы, лимиты и проверки M02](docs/M02_SECURITY.md).

## Поддерживаемые форматы

- PDF с доступным для извлечения текстом (положение источника: страница). Сканированные PDF автоматически распознаются локальным Tesseract OCR (русский и английский языки), а исходный файл сохраняется без изменений. Зашифрованные и повреждённые PDF отклоняются; OCR не выполняется для изображений вне PDF.
- DOCX (абзацы и строки таблиц), TXT и MD (диапазоны строк), CSV (строки и числовые агрегаты), XML (путь элемента).
- XLSX и XLS (листы, строки и ячейки), PPTX (слайды и блоки текста), HTML/HTM (без выполнения скриптов), JSON (JSON path) и EPUB (главы).
- Максимальный размер одного файла: 25 MiB. Изображения, аудио, произвольные ZIP-файлы и URL-источники не принимаются. Полная capability-матрица MIME, проверок структуры, native-парсеров, renderer’ов, ограничений и фикстур приведена в [SUPPORTED_FORMATS.md](docs/SUPPORTED_FORMATS.md); frontend/E2E и backend списки сверяются contract-тестами.

Ответы по документу имеют ссылки на серверные источники. Цитаты ведут к извлечённому фрагменту и его исходной координате; ответ без подтверждённых источников явно сообщает об отсутствии сведений. В CSV/XLSX/XLS можно выбирать лист, сортировать и фильтровать полный набор строк; номера строк и ячеек сохраняют исходные координаты для цитат. Для таблиц доступны расчёты количества строк и непустых значений, суммы, среднего, минимума и максимума отдельно по всему документу и текущему фильтру. Они считаются в коде через Decimal там, где нужна точность, а параметры расчёта сохраняются вместе с проверяемым источником. Формулы Excel не выполняются: viewer показывает только сохранённые в книге значения, а анализ и Markdown XLSX также содержат выражение формулы и явно отмечают отсутствие сохранённого результата. Пустые ячейки XLSX не превращаются в текстовые `NaN`. XLS хранит только доступные библиотеке значения; исходные выражения формул в этом формате не раскрываются.

## Закладки и дополнительные режимы анализа (M09)

Выбранный источник можно сохранить как закладку, добавить или изменить заметку до 500 символов, перейти обратно к координате в оригинале либо удалить запись. Закладка хранит ID источника и его версию, поэтому повторная обработка документа не переназначает её на похожий текст. Четыре дополнительных режима (**Кратко**, **Подробно**, **Задачи**, **Риски и неясности**) запускаются только по явному нажатию и сохраняются отдельно от семи основных карточек. Ответы привязаны к версии анализа, модели, reasoning и серверным source IDs; неизвестные citation labels от модели отбрасываются. Для исполнителя и срока в режиме задач явно сообщается, если поле не найдено; в режиме рисков модель просит отделять интерпретацию от подтверждённых фактов. Контекст одного запроса ограничен `ADDITIONAL_ANALYSIS_MAX_SOURCES` (по умолчанию 8, диапазон 1–20), `ADDITIONAL_ANALYSIS_MAX_SOURCE_CHARS` (по умолчанию 1200, диапазон 100–5000) и общим лимитом `MODEL_CONTEXT_CHARS`.

## Экспорт анализа (M10)

После обработки документа кнопка **Экспорт** позволяет скачать отчёт в Markdown или PDF. Можно выгрузить весь анализ, отметить отдельные ответы или сохранить текущую переписку; при экспорте анализа включаются выбранные сохранённые результаты M09. Экспорт собирается из snapshot выбранной версии: новый запрос к модели не выполняется, citations сверяются с этой версией и серверными source IDs. В отчёт входят название документа, дата, модель и уровень reasoning, версия обработки, примечания об OCR/резервном парсере и нумерованные источники с координатами и выдержками. PDF поддерживает кириллицу, таблицы с повтором заголовка на новых страницах, код и безопасные ссылки; пользовательский HTML не исполняется. Имена файлов очищаются перед отправкой, а временные адреса приложения в источники не попадают. Контракт API описан в [docs/M09_M10_ANALYSIS_EXPORT.md](docs/M09_M10_ANALYSIS_EXPORT.md).

## UX

Слева находится библиотека устойчивых чатов: загруженный документ создаёт связанный с ним чат, а **Помощь по приложению** создаёт отдельный разговор без документа. В строке видны тип и название (имя файла, первый вопрос или метка помощи), число сообщений и последняя активность. Чаты можно переименовывать и закреплять; поиск выполняется по названию, имени исходного файла и тексту сообщений, показывает совпавший фрагмент и открывает нужное сообщение. Библиотека загружается страницами и не читает полную переписку каждого чата при запуске. История вопросов и ответов хранится в PostgreSQL, поэтому обновление страницы не сбрасывает работу; выбранный чат дополнительно восстанавливается в этом браузере. Для продолжения нажмите на чат в списке.

Предпросмотр оригинала и семь карточек находятся по центру, чат — справа. В просмотрщике доступны вкладки **Оригинал** и **Markdown**, а готовый Markdown можно скачать. Панель поиска позволяет искать буквальную фразу отдельно по всему оригиналу или по всему Markdown; счётчик включает результаты из ещё не загруженных страниц, стрелки переходят между совпадениями, Enter/Shift+Enter работают как «далее/назад», Escape очищает запрос. Поиск локальный и не запускает модель. Для PDF и DOCX отображаются страницы, для TXT/MD/XML/JSON/HTML — безопасный исходный текст, для CSV/XLSX/XLS — таблица, для PPTX и EPUB — структурированные исходные блоки. Найденное совпадение открывает соответствующую страницу, OCR-область, ячейку, слайд или абзац и выделяет текст; на вкладке Markdown используются собственные координаты Markdown. Нажатие на цитату прокручивает оригинал к странице, абзацу, строке, слайду, листу или узлу и выделяет связанный фрагмент; при неточном сопоставлении показывается ближайшая область. Если MarkItDown недоступен, документ остаётся готовым в резервном native-режиме с предупреждением. Ответы ассистента в чате отображаются как безопасный GFM Markdown: поддерживаются заголовки, списки, выделение, блоки кода, таблицы и ссылки, а маркеры цитат остаются интерактивными кнопками. Ширина чата меняется мышью или клавишами-стрелками и сохраняется в браузере; панель можно свернуть или развернуть. На узком экране библиотека и чат открываются как выдвижные панели.

Визуальный язык следует приложенному брифу на основе Uber: Inter, чёрно-белая палитра, отступы по шкале 4 px, пилюли для кнопок и карточки с радиусом 16 px. Это вдохновлённая адаптация, а не официальный продукт Uber.

PDF.js renderer и его worker вынесены в отдельные assets и загружаются только при открытии оригинала PDF. Стартовый экран и просмотр документов других форматов не загружают их. Если PDF chunk или worker временно недоступен, пользователь может повторить загрузку; выбранная citation сохраняется. `npm run build` проверяет Vite manifest и ограничивает gzip-размер стартового JavaScript 80% от зафиксированного M20 baseline.

## Разработка

- `backend/` — FastAPI, SQLAlchemy, миграции Alembic, парсеры, поиск и Codex SDK.
- `frontend/` — React, TypeScript, Vite, nginx.
- `docker-compose.yml` поднимает PostgreSQL/pgvector, API и веб-клиент.

API доступно через `/api/v1`; библиотека чатов — `GET /api/v1/chats/library` (поиск `q`, пагинация `offset`/`limit`), а настройки отдельного чата читаются и обновляются через `GET`/`PATCH /api/v1/chats/{chat_id}` с проверкой `expected_revision`. Совместимый `GET /api/v1/chats` сохранён для старых клиентов. Интерактивная OpenAPI-справка — [http://localhost:5173/docs](http://localhost:5173/docs). API-порт остаётся внутри сети Docker Compose.

Управление перепиской и повторным анализом описано в [документе M12](docs/M12_CHAT_CONTEXT.md): сообщения и прерванные ответы сохраняются в PostgreSQL, новый контекст отделяет историю без её удаления, а повторный анализ создаёт отдельную версию на выбранных модели и reasoning, переиспользуя текущие OCR и индекс.

## Проверки

Локальные проверки устанавливаются отдельно от runtime-зависимостей:

```powershell
cd backend
python -m pip install -r requirements-test.txt
python -m pytest -q
python -m coverage run --source=app -m pytest -q
python -m coverage report -m

cd ..\frontend
npm ci
npm test
npm run build
```

Backend-тесты покрывают парсеры и карту источников, обработку Markdown/резервный режим,
индексацию и поиск, анализ с цитатами, закладки, дополнительные режимы анализа и экспорт, Codex-настройки, API-хелперы и защиту локальных
запросов. Frontend-тесты проверяют доступность сворачивания библиотеки, безопасный Markdown,
режимы просмотра документа и целевые motion-контракты. Проверка покрытия выполняется для
unit-тестов backend; API-эндпоинты и полный пользовательский поток дополнительно проверяются
Compose-интеграционными тестами ниже.

Полная приёмка запускает backend unit с coverage, frontend contracts/build, браузерные E2E, API-интеграционные тесты, Linux-аудит безопасности и проверки backup/restore в отдельном Compose-проекте с уникальными именем и volumes на порту 5175. Рабочая библиотека, volumes и аккаунт Codex не используются. Первое скачивание Chromium и локальной модели embeddings требует интернета; синтетические документы не отправляются в облако. Отдельная opt-in проверка live Codex описана в [docs/E2E_TESTING.md](docs/E2E_TESTING.md); синтетический provider её не заменяет.

```powershell
py -3.12 -m venv backend/.venv
backend/.venv/Scripts/python.exe -m pip install -r backend/requirements.txt -r backend/requirements-test.txt
pwsh -File scripts/test-e2e.ps1
```

Для короткого браузерного прогона можно передать Playwright-фильтр: `pwsh -File scripts/test-e2e.ps1 -PlaywrightGrep "Bookmarks and supplementary analyses"`.
