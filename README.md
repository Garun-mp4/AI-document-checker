# AI Document Checker

Локальный веб-сервис для чтения PDF, DOCX, TXT, MD, CSV и XML: семь ответов по документу, поиск с цитатами и чат. Интерфейс и все данные приложения рассчитаны на одного пользователя.

## Запуск

Требуются Docker Desktop с Compose и интернет для первичной загрузки контейнеров и локальной модели эмбеддингов.

1. Скопируйте `.env.example` в `.env` и при желании задайте собственный пароль PostgreSQL латинскими буквами и цифрами. Не добавляйте `.env` в Git.
2. В каталоге проекта выполните:

   ```powershell
   docker compose up --build -d
   ```

3. Откройте [http://localhost:5173](http://localhost:5173).
4. Нажмите **Подключить Codex**, откройте ссылку активации и введите показанный одноразовый код. Состояние входа хранится в отдельном Docker volume.
5. Загрузите документ. После локального извлечения текста и индексации появятся карточки анализа; вопросы чату можно задавать в правой панели.

Проверить состояние контейнеров: `docker compose ps`. Посмотреть сообщения API: `docker compose logs -f api`. Остановить приложение: `docker compose down`. Обычная остановка сохраняет БД, загруженные документы, модель и вход Codex. Команда `docker compose down -v` удалит эти volumes вместе с данными.

## Обработка данных

Оригиналы и извлечённый текст хранятся в Docker volumes на локальной машине. Векторные эмбеддинги создаются локальной моделью `intfloat/multilingual-e5-small`, а PostgreSQL с `pgvector` хранит текстовые и векторные индексы. Для ответов в облачный Codex передаются только выбранные релевантные фрагменты документа и вопрос. Сам файл и локальный индекс туда не загружаются.

Для ответов используется официальный Python SDK `openai-codex`, авторизация Codex через аккаунт ChatGPT и модель `gpt-6-luna` с уровнем reasoning `medium`. OpenAI API key не нужен. Нужны интернет, активный вход в Codex и доступность модели в аккаунте; приложение показывает ошибку вместо автоматического выбора другой модели. Лимиты и доступность зависят от аккаунта Codex.

## Поддерживаемые форматы

- PDF с доступным для извлечения текстом (положение источника: страница). Зашифрованные, повреждённые и сканированные PDF отклоняются; OCR не реализован.
- DOCX (абзацы и строки таблиц), TXT и MD (диапазоны строк), CSV (строки и числовые агрегаты), XML (путь элемента).
- Максимальный размер одного файла: 25 MiB. XLSX, DOC, изображения и другие форматы не принимаются.

Ответы по документу имеют ссылки на серверные источники. Цитаты ведут к извлечённому фрагменту и его исходной координате; ответ без подтверждённых источников явно сообщает об отсутствии сведений. Для CSV сумма и среднее числовых столбцов рассчитываются в коде.

## UX

Библиотека документов находится слева, рабочая область с текстом и семью карточками — по центру, чат — справа. Ширина чата меняется мышью или клавишами-стрелками и сохраняется в браузере; панель можно свернуть или развернуть. На узком экране библиотека и чат открываются как выдвижные панели.

Визуальный язык следует приложенному брифу на основе Uber: Inter, чёрно-белая палитра, отступы по шкале 4 px, пилюли для кнопок и карточки с радиусом 16 px. Это вдохновлённая адаптация, а не официальный продукт Uber.

## Разработка

- `backend/` — FastAPI, SQLAlchemy, миграции Alembic, парсеры, поиск и Codex SDK.
- `frontend/` — React, TypeScript, Vite, nginx.
- `docker-compose.yml` поднимает PostgreSQL/pgvector, API и веб-клиент.

API доступно через `/api/v1`; интерактивная OpenAPI-справка — [http://localhost:5173/docs](http://localhost:5173/docs). API-порт остаётся внутри сети Docker Compose.

## Проверки

Чтобы прогнать проверки парсеров в локальной среде Python, установите `backend/requirements-test.txt`, перейдите в `backend/` и выполните `python -m pytest`. Тесты покрывают координаты источников, CSV-разделители и точные числовые агрегаты, а также ошибки PDF, DOCX и XML.
