# M12: сообщения, контекст и повторный анализ

M12 сохраняет связь вопроса и ответов, отделяет новые контексты на сервере и делает повторный анализ версионным. Документ, предыдущие сообщения и опубликованные карточки остаются доступны.

## Переписка

- `GET /api/v1/chats/{chat_id}/messages` возвращает всю сохранённую переписку с полями `context_epoch`, `reply_to_message_id`, `generation_status`, `generation_error`, `model`, `reasoning_effort` и `source_version`.
- `POST /api/v1/chats/{chat_id}/messages` создаёт вопрос и ответ. Поток SSE передаёт события `started`, `sources`, `delta`, затем `done` или `error`. Сервер сохраняет реальные идентификаторы и метаданные до отправки событий.
- `POST /api/v1/chats/{chat_id}/messages/{user_message_id}/retry` повторно отправляет исходный вопрос. Новый ответ сохраняется отдельной попыткой и ссылается на тот же вопрос.
- `POST /api/v1/chats/{chat_id}/messages/{assistant_message_id}/stop` останавливает активный ответ. Частичный текст имеет статус `interrupted`; его можно повторить. Оборванный ответ никогда не помечается завершённым.
- `POST /api/v1/chats/{chat_id}/context` увеличивает `context_epoch`. Старые сообщения остаются видны, но не передаются в контекст модели для новых вопросов.
- `DELETE /api/v1/chats/{chat_id}/messages/{message_id}` физически удаляет вопрос и все связанные ответы, если передан ID любого элемента такой пары. Документ не удаляется. UI требует подтверждение и поясняет точный объём удаления.

В prompt передаются только сообщения текущего контекста, завершённые ответы и до 32 последних элементов в пределах 12 000 символов. Повтор вопроса строится с историей, существовавшей до исходного вопроса. Streaming/interrupted-ответы в историю не включаются. После перезапуска API оставшийся статус `streaming` при следующем чтении истории восстанавливается как `interrupted`.

## Версии анализа

- `GET /api/v1/documents/{document_id}/versions` возвращает готовые версии, версию источников, выбранную модель/reasoning и активный статус.
- `GET /api/v1/documents/{document_id}/insights?version={number}` возвращает карточки выбранной готовой версии. Без параметра возвращается текущая активная версия.
- `POST /api/v1/documents/{document_id}/analysis/rebuild` принимает `model`, `reasoning_effort` и `expected_source_version`. Backend проверяет доступность выбора и версии источников; устаревшая версия даёт `409`, неподдерживаемый выбор — `422`.

Повторный анализ использует готовую версию chunks, поэтому не запускает повторно OCR, MarkItDown или embeddings. Новые карточки и версия анализа публикуются атомарно после успешного завершения. До этого активными остаются прежние карточки; успешная и исходная версии доступны для просмотра. Выбор модели для повторного анализа одноразовый и не меняет сохранённые предпочтения Codex. Недоступная модель не подменяется автоматически.

Миграция `0009_chat_context_analysis` добавляет поля сообщений/контекста и метаданные анализа с backfill связей старых ответов и атрибуции доступных прошлых версий. Оригиналы и история чатов не переписываются миграцией.
