# M02 — безопасность загрузки и артефактов

## Границы защиты

Приложение остаётся локальным однопользовательским сервисом. Защита рассчитана на недоверенные загруженные документы: подмену формата, архивные бомбы, внешние ресурсы, XML-сущности, опасные пути и чрезмерное потребление ресурсов. Публичный многопользовательский deployment, авторизация API и полноценная песочница файловой системы не входят в M02.

Оригинал сохраняется неизменным. Конвертация, native parsing, OCR, сопоставление Markdown и просмотр таблиц выполняются в одноразовых дочерних процессах. Это изоляция ресурсов и сети, а не сохраняемая очередь заданий из M03.

## Приём файла

- Nginx ограничивает HTTP body 26 MiB и время ожидания следующей части body 30 сек. ASGI независимо считает реально полученные байты, в том числе при chunked-загрузке без `Content-Length`.
- Лимит самого файла — 25 MiB: данные записываются порциями по 1 MiB в эксклюзивно созданный UUID-файл. Переполнение, отмена и отказ проверки удаляют только созданный неполный файл.
- Проверяются расширение, допустимый MIME и сигнатура/структура. Пустой/неизвестный browser MIME и `application/octet-stream` допустимы только при успешной проверке содержимого. EPUB принимает также browser alias `application/epub` и ZIP MIME.
- DOCX/XLSX/PPTX/EPUB проверяются до создания записи документа: не более 5000 записей, 100 MiB распакованного объёма, 32 MiB на ресурс. Проверяются фактическое чтение и CRC, обязательные части контейнера, дубликаты, шифрование, ссылки и внутренние пути.
- Запрещены абсолютные пути, traversal, обратные слеши, симлинки, внешние Office-ресурсы и опасные URL. Обычные HTTP(S)/mailto гиперссылки допускаются; они не загружаются конвертером. Относительные ссылки между частями пакета допускаются только внутри пакета.
- XML, включая внутренний XML архивов, обрабатывается `defusedxml` без DTD, внешних сущностей и внешних обращений. HTML остаётся экранированным исходным текстом; script/style/iframe/object не входят в native-текст анализа.
- Повреждённый файл получает 400/415/422, превышение размера — 413. Структурно допустимый, но нечитаемый документ получает существующее состояние ошибки обработки, без готового анализа.

## Ограничения обработчика

| Предел | Значение по умолчанию |
| --- | --- |
| Одновременные тяжёлые операции | 2 |
| Время одной операции | 180 сек; MarkItDown — 120 сек |
| CPU | 90 сек на каждый процесс; весь контейнер — 2 CPU |
| Адресное пространство процесса | 1536 MiB |
| Файл/IPC-результат операции | 64 MiB |
| Страницы PDF / слайды PPTX | 500 |
| Извлечённый текст | 5 млн символов |
| OCR | 100 страниц; 5 млн символов; 90 сек на вызов инструмента; общий предел операции 180 сек |
| Raster OCR | 20 млн пикселей на страницу; по одной странице в памяти |
| Таблица | 100 000 строк, 500 столбцов, 200 листов |
| API-контейнер | 4 GiB RAM, 2 CPU, 512 процессов, `/tmp` 256 MiB |

Параметры ограничений задаются в `app/config.py`; существующие OCR-параметры сохраняются в Compose. Linux worker применяет `RLIMIT_AS`, `RLIMIT_CPU`, `RLIMIT_FSIZE`, `RLIMIT_NOFILE`, отключает core dump. `libseccomp2` запрещает создание сетевых сокетов и `connect`; фильтр наследуется Poppler/Tesseract. При отсутствии фильтра обработка не запускается. API сохраняет сетевой доступ к БД и Codex.

Worker не наследует переменные с секретами БД/Codex. Он работает в собственном временном каталоге, использует ограниченный безопасный снимок оригинала для сторонних конвертеров. После таймаута/отмены завершается группа процессов и удаляется временный каталог. Root filesystem контейнера read-only, capabilities удалены, `no-new-privileges` включён. Writable volumes с документами, embeddings и авторизацией сохранены.

На Windows при запуске backend вне Docker доступны родительские ограничения времени/размера результата и проверки путей. Linux resource/seccomp и завершение всей группы дочерних инструментов проверяются и гарантируются для штатного Compose. Worker работает с правами API; ограничения не являются отдельной файловой песочницей против эксплуатации native-библиотеки. Для такого усиления нужна отдельная container/namespace-песочница.

## Доступ к артефактам и ошибки

- Путь должен быть непосредственным файлом upload directory и соответствовать UUID запрошенного документа. Подмена указателя в БД не позволяет прочитать или удалить артефакт другого документа.
- Отвергаются симлинки и hardlink при чтении. Linux `O_NOFOLLOW` и открытый дескриптор предотвращают замену проверенного pathname другим файлом между проверкой и отправкой.
- Производные файлы записываются через временный соседний файл, `fsync` и атомарный `replace`. Исходный `.md` не совпадает с производным `.markdown.md`.
- Имена скачиваний очищаются от путей, управляющих символов и CRLF. MIME задаётся сервером; HTML/XML оригиналы выдаются как `text/plain`. Ответы содержат `nosniff`, CSP `sandbox; default-src 'none'`, `no-store`, безопасный `Content-Disposition`. PDF сохраняет MIME и поддержку одиночного byte Range.
- Внутренние ошибки возвращают нейтральное сообщение. В логах остаются категория ошибки и служебный ID, без traceback с SQL-параметрами, текста документа, SDK-секретов и полного ответа модели. Фоновые исключения явно наблюдаются; stderr недоверенного конвертера не публикуется.
- При отмене на границе DB commit уже сохранённый документ и его оригинал сохраняются; обработка планируется. Незавершённый commit не оставляет принятый документ с удалённым оригиналом.

## Проверка

`pwsh -File scripts/test-e2e.ps1` использует исключительно `document-checker-e2e`. Помимо проверки всех 13 расширений выполняются unit-тесты защит, браузерные отрицательные сценарии и Linux-аудит реальных ограничений памяти/CPU/сети/файлов. Отдельно проверяются настоящий chunked HTTP multipart и лимит nginx. Fixtures синтетические, рабочие документы и авторизация не используются.

Актуальные результаты фиксируются в [TESTING_REPORT.md](../TESTING_REPORT.md). M03 не реализуется в этом изменении.
