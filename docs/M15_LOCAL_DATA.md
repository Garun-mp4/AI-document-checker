# M15: локальные данные, обслуживание и резервные копии

Интерфейс **Локальные данные** показывает документы и чаты, объёмы оригиналов, Markdown, карт источников, индексов, parser cache, модели embeddings и распознанных временных файлов. Обновите сводку после долгой обработки или удаления.

## Что хранится и что передаётся

- PostgreSQL volume содержит записи документов, чаты и сообщения, фрагменты источников, векторные индексы, анализ, версии обработки и журнал обслуживания.
- `document_uploads` содержит оригиналы, Markdown, карты источников и ограниченный кэш парсеров.
- `embedding_cache` содержит загруженные файлы локальной модели и повторно создаваемый кэш векторов.
- `codex_auth` отдельно хранит локальную авторизацию Codex. Она не очищается действиями M15 и не удаляется при очистке библиотеки.
- Для генерации анализа отправляются вопросы по карточкам и ограниченные найденные фрагменты. Для ответа чата отправляются текущий вопрос, до 32 предыдущих сообщений и найденные фрагменты. Полный оригинал и полный индекс не отправляются.

Диагностический ZIP содержит только build/runtime версии, доступность API и базы, состояние очереди, агрегированные этапы и коды ошибок, а также обезличенные длительности. В него не включаются тексты, имена файлов, пути, содержимое авторизации, env-переменные или адрес базы. Состояние healthcheck самого worker-контейнера приложение не может получить без Docker socket; архив явно указывает это ограничение.

## Действия обслуживания

- **Очистить временные файлы** удаляет только распознанные временные или неиспользуемые производные файлы старше 24 часов. Оригинальные файлы без ссылки из БД сохраняются для ручного восстановления. Артефакты активных заданий и версии, используемые документами, защищены.
- **Очистить восстанавливаемый кэш** удаляет только allowlist parser cache и кэш векторов. Файлы модели embeddings сохраняются: изолированные обработчики работают без сетевого доступа и используют эти веса при индексации. Оригиналы, Markdown, карты источников, индексы PostgreSQL, переписка и авторизация остаются на месте; повторная обработка может построить очищенные кэшируемые результаты снова.
- **Удалить выбранные чаты и документы** удаляет выбранные записи документов вместе с их анализом, индексом, версиями, чатом и сообщениями.
- **Удалить всю библиотеку** применяет то же удаление ко всем документам в отдельной операции.

Для трёх операций с файлами или библиотекой сначала создаётся серверный план с точным списком, количеством записей и размером. На подтверждение требуется ввести показанную фразу. План живёт 15 минут, проверяется на изменение файлов и БД, после ошибки подтверждения его можно использовать повторно. Связанные задания отменяются; если активный worker не завершил отмену, операция сообщает об этом и оставляет данные на месте. Журнал хранит только тип операции, результат, количество и объём, максимум 1000 записей за 90 дней.

M15 никогда не очищает весь Docker, host VHDX, volume PostgreSQL или volume авторизации. Не запускайте `docker compose down -v` для рабочей установки: команда удалит volumes проекта.

## Резервная копия рабочей установки

Резервная копия базы и тома документов должна соответствовать одному состоянию приложения. Для локальной копии:

1. В интерфейсе дождитесь завершения обработки и ответов. Создайте каталог резервной копии вне рабочей папки приложения:
2. Остановите API и worker, чтобы оригиналы и база не менялись во время копирования; PostgreSQL оставьте запущенным:

   ```powershell
   $backupPath = Join-Path $env:USERPROFILE 'Documents\document-checker-backup-m15'
   docker compose stop api worker web
   New-Item -ItemType Directory -Force $backupPath | Out-Null
   docker compose exec -T db sh -lc 'pg_dump -Fc -U "$POSTGRES_USER" -d "$POSTGRES_DB" -f /tmp/document-checker.dump'
   docker compose cp db:/tmp/document-checker.dump (Join-Path $backupPath 'database.dump')
   docker compose run --rm --no-deps --volume "${backupPath}:/backup" --entrypoint sh worker -lc 'tar -czf /backup/documents.tar.gz -C /data/uploads .'
   docker compose exec -T db rm -f /tmp/document-checker.dump
   docker compose start api worker web
   ```

3. Проверьте, что оба архива существуют и имеют ненулевой размер. Храните их в защищённом месте и проверяйте резервную копию восстановлением на отдельном Compose-проекте.

Для восстановления используйте отдельную копию Compose-проекта с новым именем проекта и новыми volumes. Сохраните backup-файлы вне проекта, задайте уникальное имя проекта и восстановите оба набора данных до запуска API/worker:

```powershell
$restoreProject = "document-checker-restore-$([Guid]::NewGuid().ToString('N'))"
$backupPath = Join-Path $env:USERPROFILE 'Documents\document-checker-backup-m15'
docker compose -p $restoreProject up -d --wait db
docker compose -p $restoreProject cp (Join-Path $backupPath 'database.dump') db:/tmp/document-checker.dump
docker compose -p $restoreProject exec -T db sh -lc 'pg_restore --no-owner -U "$POSTGRES_USER" -d "$POSTGRES_DB" /tmp/document-checker.dump'
docker compose -p $restoreProject run --rm --no-deps --volume "${backupPath}:/backup" --entrypoint sh worker -lc 'tar -xzf /backup/documents.tar.gz -C /data/uploads'
docker compose -p $restoreProject up -d --wait api worker
docker compose -p $restoreProject ps
```

Сначала проверьте восстановленный проект: API и worker должны быть healthy, файлы должны открываться, а сохранённые чаты и источники — соответствовать оригиналам. Только после проверки решайте, переключать ли пользователя на восстановленный проект. Не направляйте restore-команды на volumes с нужными данными.

Авторизация Codex не нужна для восстановления документов; пользователь может подключить её заново. Если требуется сохранить вход, резервируйте `codex_auth` отдельно, вручную, в зашифрованном хранилище. Этот volume содержит секреты и намеренно исключён из обычной резервной копии и диагностического ZIP.

## Изолированная проверка восстановления

Скрипт ниже создаёт временный Compose-проект со своими двумя PostgreSQL volumes и двумя volumes документов. Он копирует синтетическую запись и тестовый файл, создаёт backup обоих источников, восстанавливает их во вторую пару volumes, сверяет маркеры и удаляет только собственный проект и временный каталог с уникальным GUID:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\test-m15-backup-restore.ps1
```

Скрипт сначала проверяет доступность Docker daemon, не запускает и не перенастраивает Docker Desktop и не обращается к рабочим Compose volumes. Полная изолированная приёмка M15 запускается через `scripts/test-e2e.ps1`.
